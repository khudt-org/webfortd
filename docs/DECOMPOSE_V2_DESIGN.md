## 0. 먼저 알아야 할 사실 3가지 (현행 코드 실측)

1. **현행 주소의 `2-1-3`은 장·절 번호가 아니다.** `makeSlug`(L298~323)는 제목에서 한글을 지우고 남은 영숫자만 쓴다. 「1) 인적지원」「(1) 교수학습」「부록 1. …」이 전부 `2023-research-1`이 되고 충돌은 `-2, -3, …`으로 번호를 붙인다. 그래서 `2023-research-1-19`는 「영숫자 잔여가 1인 19번째 제목」이고, `2024-jbu-2-98`은 제목 끝 쪽수 98이 주소로 새어 들어간 것이다. 검수자가 `p-017`을 쪽수로 읽은 오해도 여기서 비롯됐다. 메모 §4.2의 「번호 기반 통일」은 개선이 아니라 **신설**이다.
2. **「관련 페이지」 블록은 어떤 스크립트도 만들지 않는다.** 350건에 들어 있는 `## 관련 페이지` 블록은 Phase 1 커밋(9b8efe4)에 content와 함께 들어온 일회성 산출물이라 재생성하면 위키링크 1,044개가 통째로 사라진다. 신규 구현 대상.
3. **재생성은 공개 상태를 되돌린다.** decomposeFile(L626, L711)이 `status: draft`·`reviewed_by: []`를 강제한다. 4종 파생 485건(2023-research 114·2023-hr 94·2024-jbu 92·2024-staff 185)은 현재 published인데 재생성 뒤 전부 초안이 된다(§5-1).

## 2. v4 정본 형식을 받는 설계

### 2.1 제목 계층 → 분해 단위
- v4는 `#`=부, `##`=「1.」, `###`=「1)」, `####`=「(1)」, `#####`=「①」, `######`=「㉠」, 부록은 `#` 부록 > `##` ◇ 부록1. > `###` [부록 1-1]. `splitLevel: 3`(=「1)」)을 기본으로 두고 `--dry-run` 건수·평균 길이를 보고 출처별 조정(「가.」 층이 두터운 2024-staff는 4 검토). 검수 5·9·11·13~17의 「제목보다 내용이 넓음」은 splitLevel=2에서 `###`이 본문에 묻힌 결과라 한 단계 내리는 것이 1차 해법.
- **부모 서문 처리(신설)**: 부모 제목과 첫 자식 사이 텍스트를 ⓐ 100자 이상이면 부모 경로 주소의 **개요 페이지**로, ⓑ 미만이면 첫 자식 본문 앞에 붙인다.
- **분해 제외 절**: 「목 차」「표 차례」「그림 차례」「참여연구진」 아래는 페이지로 만들지 않는다(검수 41과 `2023-research-1`「Ⅰ. 서론 1」의 원인).

### 2.2 쪽 주석 → source_page
- 제목 직전 줄의 `<!-- p.230 (pdf 254) -->`를 읽어 frontmatter `source_page`(문자열, 「Ⅰ-3」「목차 3」 접두 허용)·`source_page_end`·`source_page_pdf`(정수) 신설. FrontmatterSchema에 선택 필드 추가. 본문 안의 나머지 쪽 주석은 제거(RAG 청크 잡음).

### 2.3 표·서식·이미지
- 파이프 표·`<br>`·`~~`·`<mark>`는 통과. 허용 태그 화이트리스트(br, mark, table 계열, sub, sup)와 금지 태그(page_header, page_number, page_footer, u, figure, span)를 상수화.
- 5.5만 자 분할(2026-08-30 위원장 결정으로 5만 → 5.5만 상향. 델파이 2차 특수학교용 4.9만 자가 예산 4.75만을 넘어 1,411자 꼬리 문서가 생겼고, 예외 병합 대신 한도를 올렸다. 값은 `decompose-source.ts` SPLIT_MAX_CHARS와 `validate-frontmatter.ts` BODY_MAX_CHARS 두 곳): 표 블록 경계에서만 절단, 제목 `(1/2)`, 주소 `-pt1`/`-pt2`. 단일 표가 한도 초과면 경고만.
- 이미지: 「교체」→「보존+마커」. TODO 마커 다음 줄에 원문 `(이미지: alt)`를 남기고, image-mappings apply가 마커와 alt 줄을 함께 치환.

## 3. 규칙별 구현 계획

### 3.1 번호 파서(신설) `parseOutlineNumber(text, level)`
| 패턴 | 정규화 |
|---|---|
| Ⅰ.~Ⅻ. | 1~12 |
| 1. / 1) / (1) | 정수 |
| ①~⑳ | 1~20 |
| ㉠~㉭ | 1~14 |
| 가. 가) / A. | ㄱㄴㄷ 순 / 알파벳 순 |
| 부록 / ◇ 부록1. / [부록 1-1] | `app` / 1 / 1(부모 app-1 아래) |
| 번호 없음 | `x<n>`(부모 경로 아래 번호 없는 형제 순번) |

### 3.2 주소 = 출처 접두 + 경로
- 주소 = prefix + 부에서 자기 수준까지 **전 조상 번호**. 「Ⅱ부 > 2. > 1) > (1) 교수학습」 → `2023-research-2-2-1-1`. 장마다 반복되는 「(1) 교수학습」은 조상 경로가 달라 충돌이 구조적으로 사라진다. 부록 `2023-research-app-1-1`, 개요 페이지는 부모 경로 그대로, 분할 `-pt1`.
- 같은 경로에 같은 번호 두 번(원본 번호 오류)이면 `-d2` + 경고 목록. `p-`·`appendix-NNN`·충돌 카운터·p- 재폴백 삭제. 불통과는 fatal.
- 2020 단체협약(art-NNN)은 범위 밖: `slugScheme: 'article' | 'outline'` 분기로 기존 함수 보존.
- 번호 없는 제목은 메모의 「직전 번호 + -x1」 대신 **부모 경로 + x<n>**(형제 삭제 시 번호가 밀리지 않음).

### 3.3 §4.1 규칙
- 제목 범위=내용 범위: 본문의 제목 아닌 줄이 자기 수준 이상 번호 패턴으로 시작하면 `range` 경고. 정본이 결정론 제목이므로 이 경고는 곧 2층 승격 누락 신호.
- 제목 유일성: 출처 내 title 중복이면 `parent_headings` 마지막 값 접두(「뇌병변장애 고려 사항」), 그래도 중복이면 한 단계 위까지.
- 제목 끝 쪽수: 목차 제외로 본문 제목엔 남지 않아야 하며, 안전망으로 `\s\d{1,3}$`이 source_page와 같으면 제거.
- parent_headings 오인 차단: `^(<\s*표|〈표|<\s*그림|참\s*고\b|TIP\b|Q\s*&\s*A)` 제목 후보 제외 → 본문 굵게로 강등.
- 빈 조각 병합: 100자 미만이면 다음 형제 본문 앞에 `## 원제목` 소절로 병합(검수 31).

### 3.4 관련 페이지 블록(신설 → 2026-09-23 개정)
본문 끝에 `## 관련 페이지` + `- [[slug|제목]] (원본 230쪽)`. 순서는 **상위 문서(부모 절의 개요 페이지, 있을 때) → 하위 문서(이 페이지가 개요 페이지일 때 그 자식들) → 형제 문서(같은 부모 경로)**이고 세 종류 중 하나라도 있으면 블록을 만든다. 형제만 있으면 평면 목록, 상위·하위가 하나라도 있으면 `### 상위 문서`·`### 하위 문서`·`### 형제 문서` 소제목으로 나눈다. 목록 20건 초과면 앞뒤 10건씩. (개정 근거: 3차 검수 22·44번 — 「…다음과 같음」으로 끝나는 부모 문서에 자식 목록이 없어 2차·3차 내내 유실로 오해됐다.)

### 3.4b 제목 직전 라벨 귀속(2026-09-23 신설)
제목 바로 앞의 한 줄 라벨(`[별지 제N호 서식]`·`[서식 …]`·`[부록 …]`, 사이에 빈 줄·쪽 주석만 허용)은 **다음 제목의 문서에 붙인다** — 제목 아래 첫 줄로 옮기고 쪽 주석은 제자리에 둔다(쪽 계산 불변). 3차 검수 34번: 서약서 문서 끝에 다음 서식의 이름표가 남고 자기 이름표는 앞 문서로 갔다. 인사관리·중부대 부록2 서식 4건씩이 대상이다.

### 3.5 대응표·참조 갱신(신설 스크립트 2개)
- `scripts/slug-migration.ts`: 재생성 **전에** 구 content를 떠 두고 ① 번호·쪽수·공백 제거한 제목 일치 → ② 본문 3-gram Jaccard(임계 0.5) → ③ 미매칭 순으로 `docs/slug-migration-2026-08.csv`(old_slug, new_slug, old_title, new_title, method, score). v4는 v3와 텍스트가 달라 ②가 필수.
- `scripts/apply-slug-migration.ts`: `_axis-overrides.json`·`_image-mappings*.json`·`_slug-raster-map.json` 키, `media-curation.ts`·`wiki-role-entries.ts`·`wiki-popular.ts` 문자열, faq·resources·agreements의 수동 `[[링크]]` 치환. 미매칭·1:N은 치환하지 않고 목록 출력. 검수 시트 xlsx는 Drive 쪽에서 같은 CSV 적용.
- 주의: `_image-mappings.json` 키의 세 번째 세그먼트(파일 내 순번)는 페이지 경계가 바뀌면 어긋난다. 키를 `<slug>#<source>#<alt 앞 40자 해시>`로 바꾸는 편이 안전(§5-3).

### 3.6 검증 게이트(`validate-frontmatter.ts` 확장)
1. 파서 태그 잔존 → 빌드 실패. 2. 끊긴 위키링크 → 오류(현재는 기록만). 3. 출처별 title 중복, parent_headings 불일치 → 오류. 4. 본문 100자 미만·5.5만 자 초과 → 오류. 5. 4종 주소에 `-p-`·`appendix-` 포함 → 오류(재발 차단). 6. 테스트 A·C·F 갱신 + 경로 주소·관련 페이지·source_page 신규 케이스.

## 6. 그 밖의 위험

- `--reset` 전체 실행은 단체협약(2020-ca, content(edit) 커밋 2건)도 지우므로 `--file`로 4종만 돌리거나 CA를 `skipRegenerate`로 잠근다.
- PDF 경로로 가는 문서(HWP 원본이 없는 경우)는 제목 계층이 덜 깨끗해 범위 경고가 많이 뜰 것이므로 게이트 「범위 경고 0」은 출처별로 판정한다.
- `<br>`·`<mark>`·`~~`·`[[slug|제목]]` 렌더는 수행사 확인 전까지 webfortd 기준으로만 검증(메모 §8).
